# ModSync

轻量、可靠、零多余进程的 Minecraft 客户端模组同步更新系统。

---

## 架构概览

ModSync 专为自建服或中小型社区设计，解决客户端模组版本不一致问题。整体分为两部分：

1. **发布服务端 (Server)**：
   - 极简单容器架构，内置轻量 Web 控制台，纯 JSON 文件持久化，无需外部数据库。
   - 监听宿主机指定分发目录，扫描新增、变动同名文件及删除项，全文 SHA-256 哈希比对。
   - 具备发布核验、下载启停控制、只读 Token 鉴权以及**一键动态生成更新器 JAR** 机制。
2. **客户端模组 (Client Mod)**：
   - 运行于 Minecraft 游戏主菜单与多人游戏界面，采用**纯手动交互触发**（零静默联网、零自动弹窗、零后台轮询）。
   - 本地比对完整目标清单，支持增量下载覆盖、跳过同名不同文件、智能清理旧受管 Mod，且**严格保留玩家自装的第三方模组**。
   - 支持一键修复恢复官方基准，内置更新器自我保护机制。

## 快速开始

### 1. 服务端一键部署 (推荐)

在 Linux 服务器（Debian / Ubuntu / CentOS 等）上克隆项目并执行一键部署脚本：

```bash
git clone https://github.com/Jees996/mc-modsync.git
cd mc-modsync
chmod +x install.sh && ./install.sh
```

脚本将自动检查 Docker 与 Compose 环境、创建所需分发目录（默认 `dist/client_mods`）、生成随机安全凭据并启动服务。

*(亦可进入 `deploy/` 目录复制 `.env.example` 为 `.env` 手动配置后运行 `docker compose up -d` 启动)*

启动完成后，在浏览器中打开控制台地址（如 `http://<your-server-ip>:25580`）登录后台。

### 2. 发布模组更新

1. 将需分发的客户端 `.jar` 文件复制到服务端配置的模组分发目录（默认 `dist/client_mods`）。
2. 在后台填写更新说明，点击 **“扫描文件变动”** 查看增删改差异。
3. 点击 **“确认发布此版本”**，系统原子落盘发布清单并生成最新版本号。

### 3. 一键生成客户端更新器

在后台 Web 控制台的 **“生成客户端更新器”** 区域：
1. 选择匹配您客户端的加载器版本模板（如 `Forge 1.20.1` 或 `NeoForge 26.1.2`）。
2. 输入客户端访问服务端的 URL 地址。
3. 点击 **“生成并下载更新器 (.jar)”**。
4. 将生成的 JAR 文件直接放入客户端的 `mods` 文件夹分发给玩家即可。

## 玩家使用指南

1. **检查与更新**：
   - 启动游戏，在主菜单右下角或多人游戏界面点击 **【整合包更新】** 按钮。
   - 界面将连接发布端并清晰展示版本公告与本地文件差异。
   - 点击 **【更新】** 即可增量下载缺少文件或更新变动文件。
2. **自装模组保护与修复模式**：
   - **普通更新**：严格保留玩家自行添加的小地图、光影或辅助模组，只清理先前由更新器分发的废弃模组。
   - **修复模式**：经玩家明确二次确认后，将客户端恢复为服主发布的标准列表，清理额外未知文件（更新器本体受严格保护不会被误删）。
3. **重启生效与占用处理**：
   - 更新操作采用临时文件下载、全文 SHA-256 校验与原子替换机制，避免损坏运行中文件。
   - **更新不等于热加载**：更新完成后必须**关闭游戏并重新启动**方可加载新模组。
   - 若遇到运行中文件锁定导致替换失败，界面会如实列出未完成文件，提示退出游戏后再试，绝不强行杀进程或假装成功。

## 客户端源码构建说明

如果需要自行从源码构建通用模板 JAR，请查阅 [BUILD.md](docs/BUILD.md)：

- **NeoForge 26.1.2**：
  ```bash
  cd client
  ./gradlew jar -Ptemplate=true
  ```
- **Forge 1.20.1**：
  ```bash
  cd client
  python build_forge_template.py --mc-libs <.minecraft/libraries路径>
  ```

## 安全与设计边界

- **隐私与凭据边界**：源码、模板与默认配置绝不包含任何私有密码、Token 或个人服务器信息。
- **客户端 Token 说明**：嵌入客户端 JAR 中的 Token 是公开分发的**只读下载访问凭据**（用于隔离非整合包用户防盗刷），拿到 JAR 的人可以通过解压读取该 Token，它并非不可破解的秘密。管理员密码与发布权限绝不会打入客户端。
- **零自动联网**：进入游戏时不发起任何静默网络请求，无启动弹窗，无后台轮询或遥测。
