# ModSync

轻量、可靠、零多余进程的 Minecraft 客户端模组同步更新系统。

---

## 架构概览

ModSync 专为自建服或中小型社区设计，解决客户端模组版本不一致问题。整体分为两部分：

1. **发布服务端 (Server)**：
   - 极简单容器架构，内置轻量 Web 控制台，纯 JSON 文件持久化，无需外部数据库。
   - 监听宿主机指定分发目录，扫描新增、变动同名文件及删除项，全文 SHA-256 哈希比对。
   - 具备发布核验、下载启停控制、只读 Token 鉴权以及**一键动态生成更新器 JAR** 机制。
2. **客户端模组 (Client Mod)**：
   - 运行于 Minecraft 游戏主菜单，采用**纯手动交互触发**（零静默联网、零自动弹窗、零后台轮询）。
   - 本地比对完整目标清单，支持增量下载覆盖、跳过同名不同文件、智能清理旧受管 Mod，且**严格保留玩家自装的第三方模组**。
   - 支持一键修复恢复官方基准，内置更新器自我保护机制。

## 快速开始

### 1. 服务端部署 (Docker Compose)

复制配置模板并填入您的安全凭据：

```bash
cd deploy
cp .env.example .env
# 编辑 .env 修改 ADMIN_PASSWORD 与 CLIENT_TOKEN
docker compose up -d
```

启动完成后，在浏览器中打开 `http://<your-server-ip>:25580` 登录后台。

### 2. 发布模组更新

1. 将需分发的客户端 `.jar` 文件复制到服务端配置的 `HOST_MODS_DIR` 目录中。
2. 在后台填写更新说明，点击 **“扫描文件变动”** 查看增删改差异。
3. 点击 **“确认发布此版本”**，系统原子落盘发布清单并生成最新版本号。

### 3. 一键生成客户端更新器

在后台 Web 控制台的 **“生成客户端更新器”** 区域：
1. 选择匹配您客户端的加载器版本模板（如 `NeoForge 26.1.2`）。
2. 输入客户端访问服务端的 URL 地址。
3. 点击 **“生成并下载更新器 (.jar)”**。
4. 将生成的 JAR 文件直接放入客户端的 `mods` 文件夹分发给玩家即可。

## 客户端模组开发与本地构建

若需修改或自主编译客户端更新器模板：

```bash
cd client
# 编译通用无预置配置的模板 JAR
./gradlew jar -Ptemplate=true
```

编译产物位于 `client/build/libs/`。

## 核心设计准则

- **零侵入与隐私保护**：源码与模板均不包含任何私有密钥或服务器信息；客户端绝不在游戏启动或后台静默联网。
- **强一致性下载安全**：下载前校验源文件当前哈希，防止分发未核准或传输中变动的不一致内容；客户端下载后再次执行 SHA-256 二次校验。
- **文件原子替换**：在 Windows / Linux 下采用临时文件缓冲写入与原子替换，避免直接截断运行中 JVM 可能已打开的 JAR 文件。
