# ModSync 兼容性策略与支持矩阵

本文档说明 ModSync 客户端更新器与服务端的版本兼容策略、支持矩阵及报告指引。

---

## 一、版本策略与设计原则

1. **不过度锁定构建号**：
   - 依赖项采用版本区间（如 `[47.1.0, )` 与 `[26.1.2.100, )`），而非单个精确构建号。只要底层 Minecraft 与加载器 API 未发生不兼容改动，均允许同产物加载运行。
2. **核心业务与 GUI 解耦**：
   - `UpdaterCore`：纯 Java 实现，无 Minecraft 游戏引擎或模组加载器依赖，标准 Java 17+ 环境通用。
   - `UpdaterMod` / `UpdaterScreen`：针对特定加载器（NeoForge / Forge）和对应版本的 Minecraft GUI 渲染流水线分别适配。
3. **零自动联网原则**：
   - 客户端模组不会在游戏启动时静默联网，不发起任何定时轮询或后台遥测。只有当玩家在游戏主菜单显式点击“整合包更新”按钮后，才会建立连接。
4. **状态划分**：
   - **已验证 (Verified)**：在对应 Minecraft、加载器、Java 组合上实际通过编译与端到端测试。
   - **实验兼容 (Experimental)**：基于 API 分析及版本范围声明兼容，允许用户确认后生成并测试反馈。
   - **不支持 (Unsupported)**：存在已知破坏性变动或尚未编写对应适配层，禁止生成误导性产物。

## 三、兼容性反馈

若您在特定启动器或构建号遇到兼容性异常，请通过 GitHub Issue 报告，并按模板提供信息：
- Minecraft 版本
- 模组加载器类型与具体版本（如 Forge 47.3.33 / NeoForge 26.1.2.109）
- Java 运行时版本（如 Java 17.0.15）
- 使用的启动器（如 PCL2 / HMCL / 官方启动器）
- 异常日志（**请注意抹除个人路径、服务器 IP/域名及 Token 等敏感数据**）
